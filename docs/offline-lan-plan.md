# 狼人杀离线联机方案

状态：方案阶段，尚未实现离线通信或进行实机验收。本分支只存放方案，独立于人数扩展开发；不合并、不部署到现有云服务。

配套图示：[打开 HTML 说明](offline-lan-options.html)。HTML 无外部字体、脚本或样式依赖，可下载后离线查看。

## 建议

同一现场优先采用局域网：法官端提供网页、房间服务和本地存档；玩家连接同一热点或路由器，用浏览器扫码加入。不需要互联网，也不必让每位玩家安装 App。第一步用现有电脑验证，确认有手机主持需求后再选择原生平台。

人在不同地方时，蓝牙或一个现场热点无法代替互联网。远程游戏应继续使用云端房间，单独优化弱网重连；外部线上语音房也仍需互联网。

## 拟议架构

```text
法官设备：网页资源 + 权威房间服务 + 本地存档
                       |
              同一热点 / Wi-Fi 路由器
                       |
          玩家浏览器：各自会话、身份与操作
```

- 本地服务从主机提供全部页面资源和游戏 API，不依赖腾讯云数据库、CDN、第三方字体或在线登录。
- 复用现有游戏规则和权限投影；增加本地存储与通信适配层。不要把云端鉴权密钥打包到主持程序。
- 房间二维码仅用于加入。法官权限留在主机，玩家各自建立私密会话；服务器不能向玩家发送全量身份后仅在界面中隐藏。
- 主机保存权威状态。每次操作带唯一标识和状态版本；收到确认才算成功，断线重试不重复投票、用药或推进流程。
- 持久化保存游戏状态和恢复会话。主机重启后能恢复；第一版主机故障时暂停，自动更换主机另行设计。
- 正式版本需确定通信保护方式。普通局域网 HTTP 不等于加密；HTTPS 的证书信任与手机浏览器兼容性要实际验证，不能把演示当成安全验收。

## 方案取舍

| 方式 | 适用情况 | 主要限制 |
| --- | --- | --- |
| 本地 Wi-Fi / 热点，推荐先验证 | 同场，手机系统混用，复用现有网页 | 热点连接上限、网络隔离、主机后台运行和本地地址发现 |
| 纯蓝牙原生 App | 无法建立合适 Wi-Fi 的场合 | 全员安装；多设备连接、跨平台权限、确认及恢复协议需重新适配 |
| 蓝牙发现 + Wi-Fi 同步 | 已有原生 App 后优化入场体验 | 同时维护两套通信；第一版二维码即可解决地址发现 |

Web Bluetooth 不能作为所有手机浏览器通用的联机基础。原生 Android / iOS 蓝牙能力也不代表已经验证了 12 人混合设备组网。设备和平台支持应在实施时重新核实。

## 验收边界

1. **人数**：12 位玩家加 1 位法官，按实际网络拓扑测试同时连接；法官电脑通过网线连接时，热点无线连接数可少一位。不得假定任意手机热点支持 13 台设备。
2. **离线**：先断开互联网，再加载页面、创建房间、发身份、夜间行动、投票、结束并复盘；不能只测试打开过的缓存页面。
3. **恢复**：玩家切后台和断网后恢复原席位；重复请求不重复生效；法官重启后恢复存档。
4. **隐私**：检查 API 响应、页面资源和二维码，确认其他玩家身份、法官凭证与云端密钥均不泄露。
5. **真实设备**：记录每种手机系统、浏览器、热点或路由器型号的结果。模拟浏览器测试不能代替 12 人设备验收。

本地房间不调用云服务时，其游戏同步不消耗云端请求额度。程序大小、耗电量和支持设备数在原型与实机测试前不作承诺。

## 开工前需确定

- 玩家是否都在同一现场？
- 法官可以用现有电脑，还是必须只用手机？手机属于 Android、鸿蒙还是 iOS？

确认方案后，先实现电脑主持的最小局域网原型并测试，再决定手机 App 和蓝牙是否必要。当前没有修改线上服务。
